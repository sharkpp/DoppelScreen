# glass-to-glass 実測

SPEC.md §3.3 の実測手順と、その記録。**リリースごとに同条件で測って、この表に足す。**

内訳（エンコード・ジッタバッファ・デコード）は `make e2e` が自動で測る（docs/STACK.md §2.11）。
こちらは**表示までを含めた実際の遅延**で、カメラが要るため自動化しない。

---

## 1. 何を測るか

ホスト画面が変化してから、ビューア端末の画面にそれが出るまで。**目標は 60ms 以下**
（有線 LAN、1080p60 — SPEC.md §1.3）。

`make latency-clock` が出すカウンタをホストの全画面に表示し、**ホストとビューアを 1 台の
カメラで同時に高速度撮影する。** 同じコマに写った 2 つのカウンタの差がそのまま遅延になる。

```
   ┌─ ホストの画面 ──┐   ┌─ ビューア端末 ──┐
   │      4821       │   │      4772       │     4821 − 4772 = 49ms
   │  ▁▁▁█▁▁▁▁▁▁▁▁   │   │  ▁█▁▁▁▁▁▁▁▁▁▁   │     ブロック差 3 × 16.7 ≒ 50ms
   └─────────────────┘   └─────────────────┘
```

上段のミリ秒が主、下段のブロック（1 個 = 表示 1 フレーム）が副。**桁がブレて読めないコマでも
ブロックは残る**ので、両方を見て突き合わせる。

---

## 2. 準備

| | 内容 |
| --- | --- |
| ホスト | `make macos-run` で起動 → 「配信を開始」。**ディスプレイのリフレッシュレートを確認**（省電力で落ちていると測っても意味がない。カウンタ下段の実測値を見る） |
| ビューア | 画面ごとの URL を実端末で開き、ホスト側で**承認**する。ビューアは**フルスクリーン**にする（映像をタップ） |
| ネットワーク | 有線が基準。Wi-Fi でも測るなら別の行として記録する |
| 送出解像度 | ホスト UI の「◯◯ へ配信中」の右に出る実効値をそのまま記録する。解像度追従（SPEC.md §7.1）でビューア端末ごとに変わるので、**条件として必ず控える** |
| カメラ | **240fps** 推奨（iPhone のスローモーション。設定 → カメラ → スローモーション → 1080p/240fps）。60fps だと 1 コマ 16.7ms で、目標 60ms に対して分解能が足りない |

**カウンタは毎フレーム全体が描き替わる。** 静止画を映して測ると、静止時の送出停止（SPEC.md §4.3）が
効いて何も流れず、遅延ではなく「止まっていること」を測ることになる。

---

## 3. 手順

1. ホストで `make latency-clock` → 開いたページを**全画面**にする（ブラウザの全画面表示）
2. ホストの画面とビューア端末を**並べて置く**。カメラから見て**両方が正面**になるようにする
   （斜めから撮ると液晶の視野角で数字が沈んで読めない）
3. 1 台のカメラで**両方が同時に画面内に入る**ように 240fps で 10 秒ほど撮る
4. コマ送りして、**両方の数字が同時に読めるコマ**を探す
5. `遅延 = ホストの値 − ビューアの値`。負になったら `+ 10000`（10 秒で一巡するため）
6. **離れた 10 コマ以上で読んで中央値を取る。** 1 コマの読みは撮影と表示のタイミングで
   ±1 フレームぶれる。1 回の読みを結果として採らない

## 5. 読むときの注意

- **ホストのほうが必ず新しい。** ビューアが進んで見えたら、10 秒の巡回をまたいでいる
  （`+10000` する）か、2 画面を取り違えている
- **ビューア側の数字は縮小されて写る。** 解像度追従（SPEC.md §7.1）でビューアの表示サイズに
  合わせて送るため、720p まで落ちていることがある。読めなければビューアを大きい端末にするか、
  カメラを寄せる
- **1 コマだけで判断しない。** カメラの露光とディスプレイの走査は同期していないので、
  隣り合うコマで値が 1 フレームぶん前後する
- **測る前に `make e2e` を通しておく。** 内訳（`apps/macos/build/selftest/latency.json`）を
  同じ版で取っておくと、glass-to-glass が悪化したときにどの区間かを切り分けられる
