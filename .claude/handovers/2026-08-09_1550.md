### 実装済みモジュール（SPEC.md §2.3 の責務分割に対応）

- `ScreenRecordingPermission` — `CGPreflightScreenCaptureAccess` / `CGRequestScreenCaptureAccess` とシステム設定への導線
- `DisplayInfo` / `DisplayNaming` — UI 層に `SCDisplay` を漏らさないための値型。名前とスケールは `NSScreen`（`@MainActor` 隔離）から補う
- `ScreenCapturer` — `SCStream` の管理、`.complete` 以外のフレーム破棄、統計
- `SessionController` — `@MainActor @Observable`。権限・ディスプレイ一覧・キャプチャ状態・統計を保持
- `PreviewRenderer` — キャプチャ用キューから `AVSampleBufferVideoRenderer` へ直接 enqueue
- UI: `MainView` / `OnboardingView` / `PreviewView` / `MenuBarView`

### 遅延に関わる実装上の決定

- **フレームは `MainActor` を経由しない。** `SessionController.init` で `capturer.setFrameHandler { previewRenderer.enqueue($0) }` を張り、キャプチャ用キューからプレビュー層へ直接流す
- **統計は 1 秒ごとにポーリングして読む。** フレームごとに `MainActor` へ hop すると遅延の原因になる
- `SCStreamConfiguration`: `queueDepth = 5`、`pixelFormat = 420YpCbCr8BiPlanarFullRange`、`minimumFrameInterval` は上限 fps の指定
- `.complete` 以外のフレームは破棄し `droppedFrames` として数える（静止時抑制が効いているかの指標）
- 自己プレビューは `AVSampleBufferDisplayLayer` に `CMSampleBuffer` を直接 enqueue。ピクセルのコピーが発生しない

### 依存パッケージの追加方針

**M0 ステップ 1〜3 は外部依存ゼロ**（ScreenCaptureKit / AVFoundation / SwiftUI のみ）。`stasel/WebRTC` はステップ 4（ループバック検証）で初めて追加する。使う段になってから足す。

## 捨てた選択肢と理由

- **`.xcodeproj` をコミットする**: 実質バイナリで衝突必至。XcodeGen で生成する
- **`NSLock.lock()` / `unlock()`**: Swift 6 では async コンテキストから使用不可（コンパイルエラー）。`withLock { }` に統一した
- **プレビューへ `CVPixelBuffer` → `CGImage` 変換して SwiftUI `Image` で描画**: CPU コピーが発生し、本設計の「ピクセルをコピーしない」方針に反する
- **`SCDisplay` を UI 層まで持ち回る**: Sendable でないため `@MainActor` 境界を越えられない。`DisplayInfo`（Sendable な値型）に変換して渡す
- **メニューバー常駐（`LSUIElement = true`）を今入れる**: 初回起動でウィンドウが出ず、オンボーディングが見えない。通常ウィンドウ + `MenuBarExtra` の併存とし、常駐化は M2（UI 仕上げ）で行う

## ハマりどころ

- **`NSLock.lock()` は Swift 6 の async コンテキストでコンパイルエラーになる**（`unavailable from asynchronous contexts`）。`withLock { }` を使う。戻り値を返す形（`let x = lock.withLock { ... }`）にすると `defer` より素直に書ける
- **`@Observable` クラスの `Timer` クロージャ内では `self.` の明示が必要**（`reference to property ... requires explicit use of 'self'`）
- **レイヤホスティングの `NSView` は `layer` を先に差し替えてから `wantsLayer = true` にする。** 順序を逆にするとレイヤバックのビューになり、差し替えたレイヤが描画されない
- **レイヤホスティングのビューはレイヤの geometry を自動追従しない。** `override func layout()` で `displayLayer.frame = bounds` を入れる必要がある
- **`AVSampleBufferVideoRenderer` はサンプルに `kCMSampleAttachmentKey_DisplayImmediately` を付けないと表示しない**（タイムベースを待つため）。ライブ映像では必須
- **`osascript` によるウィンドウ取得はアクセシビリティ権限が要る**ため、CLI からの GUI 検証はできなかった

## 学び

- Swift 6 strict concurrency は、最初から「Sendable な値型で境界を越える」設計にしておけばほとんど詰まらない。実際に出たエラーは 6 件で、いずれも機械的な修正だった。設計段階で `DisplayInfo` を切っておいたのが効いた
- `@unchecked Sendable` + `NSLock` は、キャプチャ用キューとメインアクタをまたぐクラス（`ScreenCapturer` / `PreviewRenderer`）で素直に機能する。actor にするとフレームごとに await が入るので不適
- 依存を「使う段になってから足す」と、ステップ 1〜3 が外部依存ゼロで完結し、ビルドが速く問題の切り分けも容易だった
