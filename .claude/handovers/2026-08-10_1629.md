## 決定事項

### プロトコル

- **接続トークンは WebSocket の最初の 1 通（`hello`）で運ぶ。** SPEC.md §5.1 の図は
  `Authorization` ヘッダだが、ブラウザの `WebSocket` はヘッダを付けられない。
  クエリに置くとログや履歴に残り、URL fragment に置いた意味が消える
- 認証は `LocalServer` が済ませ、`SessionController` には**通った接続だけ**を渡す
- **HTTPS のポートは `/config`（JSON）で答える。** HTML に埋め込むとホストが成果物を
  書き換えることになり、「ビルド済みの 1 ファイルしか知らない」前提が崩れる

### 配線

- 待受はキャプチャが動いている間だけ。映すものが無い状態でビューアを受け入れない
- 1:1。後から来た接続を採り、古い方を切る（ビューアのリロードで塞がらないように）
- 状態通知は `PeerTransport.id` で宛先を確認してから反映する。
  古い接続の「切断しました」が新しい接続を塗り潰さないため
- 証明書が用意できなくても HTTP だけで待ち受けを続ける。**HTTPS が立たないことを配信不能にしない**

### 版の固定

- swift-nio 2.101.3 / swift-nio-transport-services 1.28.0 / swift-certificates 1.13.0 を
  `project.yml` に `exactVersion` で固定した。**`Package.resolved` は `.xcodeproj` ごと
  gitignore されるため、固定は `project.yml` で行うしかない**

## 捨てた選択肢と理由

- **Playwright 同梱の Chromium で E2E**: プロプライエタリコーデックを含まず H.264 を
  デコードできない。接続はできるのに映像だけ出ない、という分かりにくい失敗になる。
  `channel: "chrome"` で実 Chrome を使う
- **HTTPS の URL を HTML に埋め込む**: ホストが成果物を書き換えることになる。`/config` にした
- **トークンを `/signal?token=` に置く**: アクセスログと履歴に残る。fragment に置いた意味が消える
- **PKCS#12 を組み立ててキーチェーンに入れる**: 秘密鍵と証明書をそれぞれ入れれば、
  キーチェーンが公開鍵ハッシュで結び付けてくれる。`security import` 系の落とし穴を回避できる
- **`--serve` の検証で `ScreenCapturer` を直接叩く**: `SessionController` を駆動すれば
  製品と同じ経路を検証できる。キャプチャ単体の検証（`--selftest`）とは役割を分ける

## ハマりどころ

### 【重大】キーチェーンの属性照合で開発用の署名証明書を消した

- `SecItemCopyMatching` / `SecItemDelete` に `kSecClassIdentity` + `kSecAttrLabel` を渡した
- **macOS の（レガシー）キーチェーンはこの絞り込みを無視する。** ラベルが一致しない
  「DoppelScreen Development」を掴み、SAN が合わないので作り直すべきと判断して**消した**
- 署名 ID が消えるとビルドが通らなくなり、作り直すと TCC から別アプリになって
  **画面収録の許可もやり直しになる**（実際にやり直した）
- 対処: 証明書を全件読んで**中身**（OU = `net.sharkpp.doppelscreen.tls`）で判定し、
  消すときは `kSecMatchItemList` で**参照そのものを指す**

### キーチェーンへの保存が 2 段階で失敗した

1. `errSecMissingEntitlement`: `kSecUseDataProtectionKeychain: false` を明示しないと
   データ保護キーチェーンへ回され、`keychain-access-groups` を要求される。
   これは実 Team ID とプロビジョニングプロファイルが要り、自己署名では付けられない
2. `errSecInvalidItemRef`: `SecKeyCreateWithData` で作った「浮いた」鍵を `kSecValueRef` で
   `SecItemAdd` に渡すと、ファイルベースのキーチェーンは項目参照として受け付けない。
   `SecKeyCreateRandomKey` + `kSecAttrIsPermanent` で**キーチェーンの中で作る**

### WebSocket 昇格で自前ハンドラが残りプロセスごと落ちる

- アップグレードで外れるのは NIO が入れた HTTP のハンドラだけ
- 自前のページ配信ハンドラが残り、`WebSocketFrame` を `HTTPServerRequestPart` として
  取り出そうとして落ちる。**症状は「アップグレードは成功するのに直後に 1006 で切れる」**
- `ChannelHandler` は `Sendable` でないため、`completionHandler` から参照を掴めない。
  名前を付けて `removeHandler(name:)` で外す

### その他

- **切断の理由を送ってから閉じるときは `ChannelHandlerContext` 経由で書く。**
  `Channel.writeAndFlush` はパイプラインの末尾から入るため `close` が先着し、理由が届かない
- **`startCapture()` は直列キューへ積むだけで、戻った時点ではまだ `.idle`。**
  「`.starting` でない」で待つと素通りする。`.running` / `.failed` で待つ

## 学び

- **キーチェーンは「属性で引いて属性で消す」をしてはいけない。** macOS のレガシー
  キーチェーンは属性を黙って無視することがあり、破壊操作が無関係な項目に及ぶ。
  引くのは中身で判定、消すのは参照で指定
- **両側から突き合わせると「送ったつもり」「映ったつもり」を潰せる。** E2E はビューア側の
  `videoWidth` とホスト側の `framesSent` の両方を見る
- **検証モードは製品と同じ経路を通すほど価値が高い。** `--serve` が `SessionController` を
  駆動しているおかげで、配線のバグ（ポート未確保、状態の取りこぼし）がそのまま出た
