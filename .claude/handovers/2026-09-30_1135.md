## 決定事項

- なし（ユーザ判断待ち）
- 推奨として提示したもの: **Flutter UI + ネイティブコア**。ただし Windows 実機での組み込み確認が通ることが前提。通らなければ Web UI 案

## 捨てた選択肢と理由

- **ネイティブのまま UI 仕様書で揃える**: 実装が 4 つ残り、差分が再発する。「完全に同一」を満たさない
- **Qt / Slint 等のクロスプラットフォーム UI**: Qt は依存が重い。Slint は Swift バインディングが無い
- **Flutter でホスト全体を共通化（ADR 0001 の案）**: 引き続き不採用。今回の案は UI 層のみで、メディア経路・証明書・キャプチャはネイティブに残すため ADR 0001 §3.1/3.4/3.5/3.6 の懸念は該当しない
- **Web UI（WebView）案は保留（第 2 候補）**: 事前に想定した「組み込みが軽い・閉じればメモリ解放」のうち、メモリは実測で Flutter より重かった（+50MB、閉じても一部しか解放されない）。優位は配布サイズのみ
- **ホスト UI を LocalServer（HTTP）で配信する形**: 承認操作が LAN から到達可能になり SPEC §5.2 の無人アクセス防止が崩れる。UI ⇄ コアはプロセス内ブリッジに限る

## ハマりどころ

- `flutter build macos-framework` は既定で署名しようとして失敗 → `--no-codesign` で生成し、アプリ側の埋め込み時に署名させる
- worktree で xcodebuild すると WebRTC の Package.resolved のリビジョン不一致で解決失敗 → メインの `Package.resolved` をコピーして解決
- `-clonedSourcePackagesDirPath` でメインの SourcePackages を共有したら xcframework 不在で失敗。**メインの `apps/macos/build/SourcePackages/artifacts/webrtc/WebRTC/` が空（8/27 から）**
- **`apps/web/package-lock.json` が `package.json` と不整合**（`npm ci`: `Missing: web@ from lock file`）。`node_modules` があると `build-viewer.sh` が `npm ci` を飛ばすため表に出ていない
- Swift 6 厳格並行性: `FlutterEventSink` が Sendable でなく `onListen` でエラー → `nonisolated(unsafe) let` で受けて回避
- **Flutter はウィンドウが隠れている（occluded）間は再描画しない**。`screencapture -l` で古い画面が撮れる。前面化で最新状態に追従する（機能上の問題はない）
- 合成クリック（CGEvent）は非アクティブ時の 1 回目がウィンドウのアクティブ化に消費される → 先に前面化してからクリック
- Playwright の同梱ブラウザが未インストール → `channel: 'chrome'` で既存の Chrome を使った
- `MainView` を差し替えると `refreshDisplays()` / 権限ポーリングも消える（画面 0/0 になる）。ブリッジ側で呼ぶ必要がある

## 学び

- macOS デスクトップでも add-to-app 相当（`macos-framework` / `swift-package`）が使える。Flutter Runner に骨格を明け渡す必要はない
- WKWebView は別プロセス（WebContent / GPU / Networking）を持つため、Flutter エンジン（プロセス内 +34MB）より重い
- Flutter エンジンは一度 run するとウィンドウを閉じても常駐する
- Pigeon の C++ 出力は Flutter の Windows client wrapper に依存する（Windows 組み込みの前提）
- ADR 0001 の「再検討の条件」1（UI の重複が負担）は M3 の時点で満たされている
