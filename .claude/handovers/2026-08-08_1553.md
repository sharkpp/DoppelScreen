## 決定事項

### 確定した事実整理

- **Flutter が削れるのは「中〜低難度で 3〜4 重複している領域」だけ。「高難度の領域」は 1 つも削れない**
  - キャプチャ: ネイティブ案 4 実装 / Flutter 案も **4 実装（変わらない）**
  - WebRTC 統合・エンコーダ制御: 4 / 1 または 4
  - LocalServer + TLS + 証明書: 3 / 2
  - UI・オンボーディング・ペアリング・QR・セッション: 3 / **1** ← 最大の効果
  - プロトコル codec: 3 / **1**
- **iOS は Flutter にできない**。Broadcast Upload Extension のメモリ上限 50MB に Flutter エンジンは入らない。Extension が PeerConnection と LocalServer を持つ必要があるため、**iOS のホスト機能は全面的に Swift ネイティブ**。結果 LocalServer は Dart 版 + Swift 版の 2 実装になり、「3 → 1」ではなく「3 → 2」に目減りする
- **Web ビューアは Flutter Web にしない**。低遅延の映像表示面に Flutter Web のレンダリングパイプラインを挟む理由がない。TypeScript を維持
- **どちらを選んでも変わらない事項**: iOS Extension は完全ネイティブ / ビューアは TypeScript

### Flutter を選ぶ場合の鉄則（ADR §4）

1. **フレームは決して Dart に入れない。** キャプチャ→エンコード→WebRTC トラックはネイティブ内で完結。Dart が触るのは開始/停止/解像度変更の指示と統計値のみ
2. **`flutter_webrtc` に送信経路を委ねない**（スパイク 1 が成功した場合を除く）。libwebrtc への薄い自前チャネルを持ち、境界を跨ぐのは SDP/ICE 文字列と制御指示だけにする
3. iOS Broadcast Upload Extension は完全ネイティブ
4. ビューアは Flutter Web にしない

### 判断のためのスパイク（1〜2 日、着手前に実施）

1. **`flutter_webrtc` の内蔵 `getDisplayMedia` で macOS → ブラウザを繋ぎ glass-to-glass を実測** ← これが決定的
2. `flutter_webrtc` が `RTCRtpSender.setParameters` / `contentHint` を公開しているか確認
3. Dart で SAN に IP を含む自己署名証明書を生成し `SecurityContext` に載せ、iPad Safari から接続できるか確認
4. macOS でトレイ常駐 Flutter アプリ（`tray_manager` + 小ウィンドウ）の体裁が UX として許容できるか判断

### 暫定的な見解（ADR §6）

- **スパイク 1 成功 → Flutter を採る。** ホスト実装の大部分が 1 つになり、ネイティブコードは iOS Extension と権限処理程度に縮む
- **スパイク 1 失敗 → 微妙。** 難所が 4 実装のまま残り、Flutter が削るのは UI とアプリロジックだけ。**4 プラットフォームすべてを本気で出す意思があるなら Flutter、macOS が主戦場で他が努力目標ならネイティブ**

## 学び

- **Flutter 化の効果は「削れる実装数」ではなく「削れる領域の難度」で測るべきだった。** 実装数だけ見ると魅力的に見えるが、削れるのは簡単な領域であり、本プロジェクトの難所（キャプチャ・遅延制御）は 1 つも減らない
- **メリットが M3 以降にしか出ない構造**。M0〜M2 は macOS のみで、その間 Flutter は「共有相手のいない抽象境界」でしかない。つまりこの判断は実質「M3〜M5 に到達する見込みへの賭け」
- 維持者の習熟度（Flutter を日常的に使っている）は、技術的優劣と同等の重みを持つ判断材料。一人〜少人数で C++/WinRT と Kotlin と Swift を並行して維持する負荷は無視できない
- Flutter デスクトップの基本単位はウィンドウであり、macOS のメニューバー常駐（`NSStatusItem` + `NSPopover`）は流儀に合わない。AppKit の糊付けが必要になり「UI を 1 実装にする」メリットを削る。トレイ + 小ウィンドウへ UX を寄せるかの判断が要る
